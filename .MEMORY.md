## Arquitectura de despliegue

### Nginx
- Upstream y include en `/etc/nginx/conf.d/app_example.conf`
- Location blocks en `/etc/nginx/conf.d/locations/mercadoAsturias.conf`
- Referencia local en `deploy/nginx/nginx.conf`
- Flujo de redirección:
  - `/mercado` → 301 → `/mercado/`
  - `/mercado/` → 302 → `/mercado/admin/login`
  - `/mercado/*` → proxy_pass a `http://127.0.0.1:8001/` (strip del prefijo)

### Supervisor
- Config: `/etc/supervisor/conf.d/mercado-asturias.conf`
- **IMPORTANTE:** el `.env` NO se carga automáticamente desde supervisor.
  Las variables deben estar en la línea `environment=` del conf:
  `DATABASE_URL`, `SECRET_KEY`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`
- Comandos útiles:
  ```
  sudo supervisorctl restart mercado_asturias
  sudo supervisorctl status mercado_asturias
  sudo supervisorctl tail mercado_asturias
  ```

### FastAPI
- `app/main.py`: `root_path="/mercado"` en el constructor de `FastAPI()`
  → necesario para que `request.app.root_path` devuelva el prefijo correcto

## Problema resuelto: panel admin sin prefijo /mercado

**Síntoma:** al hacer login el browser redirigía a `/admin/` (sin `/mercado`),
que caía en `app_example` y devolvía 404. Los links del nav también estaban rotos.

**Causa raíz:** todos los `RedirectResponse` y todos los `href`/`action` en
las templates tenían rutas hardcodeadas como `/admin/...` en vez de `/mercado/admin/...`.

**Solución aplicada en `app/admin/admin.py`:**
- Añadido helper `_prefix(request)` → devuelve `request.app.root_path`
- Todos los `RedirectResponse("/admin/...")` → `RedirectResponse(_prefix(request) + "/admin/...")`
- Todas las llamadas a `templates.TemplateResponse(...)` incluyen ahora `"prefix": _prefix(request)`
- `logout` y `toggle_comercio` carecían de parámetro `request: Request` → añadido

**Solución aplicada en templates (`templates/admin/`):**
- Todos los `href="/admin/..."` → `href="{{ prefix }}/admin/..."`
- Todos los `action="/admin/..."` → `action="{{ prefix }}/admin/..."`
- Afectados: `base.html`, `login.html`, `index.html`, `comercios_lista.html`,
  `comercio_form.html`, `categorias_lista.html`, `categoria_form.html`,
  `productos_lista.html`, `producto_form.html`
- `municipios_lista.html` no tenía links propios (solo extiende base.html)
